| # | 指摘 | 実測での確認 | 状態 |
|---|---|---|---|
| 1 | 22日以降を見るには画面の一番下まで移動してから横スクロールバーを操作する必要がある | グリッドの高さが **1037px**（20行ぶんの全高）に伸びており、横スクロールバーはその最下部にある。表示領域は 595px しかないため、バーに触るには**ページを 690px 下へスクロール**する必要がある | ✅ 再現・原因確定 |

| 3 | 月の後半を保存すると 1日付近に戻ってしまう | `handleSave` → `fetchAll()` の先頭で **`setLoading(true)`**（[ShiftFull.tsx:166](../../components/shift/ShiftFull.tsx#L166)）。`loading` 中はグリッドが「読み込み中...」に**差し替わって unmount** され（[ShiftFull.tsx:1131](../../components/shift/ShiftFull.tsx#L1131)）、再マウント時に `scrollLeft` が 0＝1日 に戻る | ✅ コードで原因確定 |

### 1〜2 の共通の真因

ページ側のラッパ `div.mx-auto.max-w-7xl`（`app/(admin)/layout.tsx`）は **`height: auto`** です。
その中の `div.flex.flex-col.h-full.overflow-hidden.shift-print-root` が `h-full`（`height: 100%`）を
指定していますが、**親の高さが auto だとパーセント高さは解決されず auto に落ちる**ため、
中身の高さぶんだけ伸びます。結果として高さの制約が下まで伝わらず、

```
main            clientH 595 / scrollH 1285   ← ここが縦スクロールしている
└ .max-w-7xl                  h 1252         （height:auto）
  └ .h-full.overflow-hidden   h 1180         ← h-full が効かず content 高さに伸びる
    └ .flex-1.overflow-auto   h 1079         ← スクロールしていない（clientH == scrollH）
      └ .h-full.min-h-[500px] h 1055
        └ グリッド .flex-1.overflow-auto   clientH 1037 / scrollH 1037 ← 縦は伸びきり
                                           clientW  642 / scrollW 1916 ← 横は 1274px 隠れている
```

**つまり「グリッドが画面内に収まっていない」ことが 1 と 2 の両方の原因**です。
グリッドを画面内に収めて内部スクロールさせれば、
横スクロールバーは常に見える位置に来て（1）、`sticky` の日付ヘッダーも即座に効きます（2）。

> 参考: 利用料金表が正しく動いているのは、スクロール容器に
> `maxHeight: calc(100dvh - 220px)` を明示しているためです。同じ手当てが要ります。

### 計測環境
実ブラウザ（ログイン済み・`/admin/shifts`・2026-08）で計測。ウィンドウ 697×655px、
表示は 32列（職員名 + 31日）× 20行。ウィンドウが広くても、職員数が増えれば同じ状態になります。

## 3. 対応方針

### 3-1. グリッドを画面内に収める（指摘 1・2 を同時に解決）

スクロール容器（[ShiftGridFull.tsx:225](../../components/shift/ShiftGridFull.tsx#L225)）に
**高さの上限**を与え、縦・横ともこの中で完結させる。

```tsx
<div
  className="flex-1 overflow-auto border-2 rounded-xl shift-grid-scroll"
  style={{ maxHeight: 'calc(100dvh - <実測して決めた固定分>px)' }}
>
```

- 上限値は topbar / パンくず / 月選択・操作行などの実測から決める（料金表は 220px）
- **`contain: paint` を併記**する。利用料金表で実証したとおり、これが無いと入れ子スクロールの
  はみ出しが祖先の `scrollWidth` に伝播してページごと横スクロールする（2026-08-08 の事例）
- `@media print` では解除する（紙には全日程を流す必要があるため）
- `thead th` / 職員名列の `sticky` は**現状のままで正しく効くようになる**（CSS の変更不要）

### 3-2. 保存してもスクロール位置を保つ（指摘 3）

原因は「再取得のたびにグリッドを unmount している」こと。次の 2 段構えにする。

1. **初回ロードだけ「読み込み中...」を出す**。以降の再取得では
   グリッドを描いたまま、操作行に控えめな更新中インジケータを出す
   （`loading` を `initialLoading` と `refreshing` に分ける）。
   → unmount されないので `scrollLeft` / `scrollTop` はブラウザが保持する。ちらつきも消える
2. 保険として、再取得の前後で**スクロール位置を退避・復元**する
   （列数が変わる月替わりでは復元しない）

あわせて、`scrollIntoView(今日の列)` を **初回マウント時のみ**に限定する
（現状は依存配列が安定しているため mount ごとに走り、再マウントのたびに今日の列へ飛ぶ）。

## 8. 別視点確認（CLAUDE.md §3）

- **高さ上限の決め打ちは壊れやすい**。ウィンドウが小さい / ブラウザのズーム時に破綻しないか実測する
- **`contain: paint` を入れ忘れない**。料金表で踏んだのと同じ横スクロール漏れが再発する
- 「読み込み中」を出さなくなることで、**保存が終わったのか分からない**状態にしない（更新中の明示は残す）
- 月切替時にスクロール位置を復元してしまうと、日数の違う月で意図しない位置になる。**月替わりは復元しない**

## 9. 実装結果（2026-08-09）

### 9-1. 実際に採った方針（計画からの変更）

「全画面に適用」の指示を受け、§3 の「画面ごとに高さ上限を決め打ちする」案は採らず、
**高さチェーンが切れている根本**を直した。決め打ちの px が消え、今後追加する画面にも効く。

| 層 | 変更 | 理由 |
|---|---|---|
| `app/(admin)/layout.tsx` / `app/(manager)/layout.tsx` | `main` を `flex flex-col` にし、コンテンツ枠を `flex-1 min-h-0` に。パンくずは `shrink-0` | 枠に**確定した高さ**を渡す。これが無いと画面側の `h-full` が解決されない |
| 各画面のルート（5画面） | `h-full` → `h-[calc(100%+3rem)] lg:h-[calc(100%+4rem)]` | ルートは `-m-6 lg:-m-8` で枠の縦パディングの外に出ているのに、`h-full` は枠の**内容高さ**しか返さないため、下に padding ぶんの死んだ余白が残っていた |
| `ShiftFull` | 本体を `flex-1 min-h-0 ... flex flex-col`、グリッドのラッパを `flex-1 min-h-0` に。`min-h-[500px]` は撤去 | 高さ制約をグリッドまで伝える。`min-h-[500px]` が上限を食い潰していた |
| `ShiftGridFull` | スクロール容器に `min-h-0` + `ref`。表示位置の初期化を `[year, month]` に限定 | 縦スクロールを容器内で完結させる／再取得で位置を動かさない |
| `ShiftFull` | `loading` を「初回」と「再取得（`refreshing`）」に分割 | 再取得でグリッドを unmount しないことで `scrollLeft` が保たれる |
| 両レイアウトの `ModeFab` | `opacity-30 hover:opacity-100 focus-visible:opacity-100` | 全画面表示だと右下セルに被るため。ユーザー選択（薄くしてホバーで濃く）|

対象 5 画面: `ShiftFull`（シフト表）/ `ScheduleFull`（利用表）/ `TransportFull`（送迎表）/
`WeeklyTransportFull`（週次送迎表）/ `DailyOutputFull`（日次出力）。

### 9-3. 判明したこと（記録）

- コンテンツ枠の `pb-24` は **実際には効いていなかった**（`lg:p-8` が後勝ちして 32px）。
  そのため「FAB 用の下余白」は元から確保できておらず、FAB は以前からセルに被りうる状態だった
- `app/globals.css` に足した `:has()` ルールは **Turbopack が拾わず**（CSSOM に存在しなかった）、
  セレクタは一致していたのに効かなかった。CSS 配管に依存せずコンポーネント側で完結させる方針に変更した
  （この試行は撤回済み。globals.css / レイアウトのクラス追加は元に戻してある）
