禹要漢 更新中 / 最終更新: 2026年05月15日14時02分

名古屋ろう国際センター職員ステーションは認定NPO法人名古屋ろう国際センター向けの統合シフト・社員管理アプリです。ろう者スタッフが使う前提で設計されており、動画や画像を豊富にいれて視覚情報を増やしていくことが可能です。

1. 全体の考え方

管理者 マネージャー シフト統括

ろう者スタッフが使うことを前提に、音声通知は一切ありません。新着や状態の変化は色・アイコン・テキストで伝えます。

画面の構成

  • 左サイドバー … メニュー
  • 上部ヘッダー … 挨拶 / 事業所セレクタ（シフトモードのみ）/ 通知ベル / ログアウト
  • 右下フローティングボタン …「社員管理モード」と「シフト・送迎モード」の切替（管理者 / マネージャーのみ）

アプリの権限

  • 管理者（本部） … NPO本部の管理者。全事業所・全機能を操作可能
  • マネージャー … 各施設の管理者や責任者。自事業所のデータのみ操作可能
  • シフト統括 … 事業所用、利用表・送迎表・利用料金などの管理アカウント。シフト・送迎・児童・希望休のみ
  • 社員 … 個別アカウント。自分のシフト閲覧と希望休の提出のみ

2つのモード（管理者 / マネージャーのみ）

画面右下のフローティングボタンで切り替えます。

  • 📋 社員管理モード … 職員・研修・お知らせ・書類などの「人」に関する作業
  • 🚐 シフト・送迎モード … シフト作成・送迎割当・利用予定・料金表など「日々の運用」
シフト統括アカウントはシフト・送迎モード固定で、社員管理モードへの切替はできません。

2. ログインと初期セットアップ

管理者 マネージャー シフト統括

ログイン

  1. /login にアクセス
  2. メールアドレスとパスワードを入力
  3. ログイン後、アプリの権限に応じて自動でダッシュボードへ移動
    • 管理者 → /admin/dashboard
    • マネージャー → /mgr/dashboard
    • シフト統括 → /admin/shifts/dashboard

パスワードを忘れた場合

  1. ログイン画面の「パスワードを忘れた方」をクリック
  2. メールアドレスを入力 → 送信
  3. 届いたメールのリンクから新しいパスワードを設定
メールリンクは約1時間で失効します。

退職者のログイン

退職処理（status=retired）された職員は、既存セッションがあっても自動で signOut され、 「退職処理済みのアカウントです」と表示されてログインできません。

招待リンクが切れた場合

招待メールのリンクは約1時間で失効します。expired 表示が出たら、 管理者に「招待を再送して」と依頼してください。

3. ダッシュボード

管理者 マネージャー シフト統括

ダッシュボードはモード別に内容が変わります。

社員管理モード（/admin/dashboard, /mgr/dashboard）

  • 今日のお知らせ / 未読の通知
  • 概要カード5種（遵守事項 / 研修 / お知らせ / 業務マニュアル / 書類）
  • 達成率カード5種
  • 休み希望の承認待ち件数
  • 在籍者数 / 退職者数

概要カードと達成率の見方（2026-05-15 仕様変更）

  • 概要カードは 「{公開件数} / {全件} 件」 形式で表示
    • 例: 「研修 8/12 件」… 公開済み 8 件、下書き含めると全 12 件
  • 達成率の分母は 公開済み (is_published=true) のもののみ が対象
  • 下書きで放置している研修やお知らせは達成率に影響しない
「書類」は仕様上 is_published 列を持たないため、概要カードは単一件数表示（例: 「書類 5 件」）。書類だけ別フォーマット。

シフト・送迎モード（/admin/shifts/dashboard）

  • 今日の利用予定（児童数 / 送迎件数）
  • 今月のシフト公開状態（下書き / 仮シフト / 公開中）
  • 直近の休み希望 / シフト変更申請
  • 主要機能へのショートカットカード（利用表・シフト表・送迎表・日次出力・業務日報・利用料金表・休み希望一覧・事業所設定・職員管理・児童管理・イベント設定）

カードをクリックすると該当ページへ遷移します。

4. 社員管理

管理者 マネージャー

社員管理モード →「社員管理」（/admin/employees, /mgr/employees）

社員を追加（招待）

  1. 右上の「社員を追加」ボタンをクリック
  2. 招待情報を入力:
    • 苗字 / 名前
    • メールアドレス
    • 役職（positions テーブルから選択）
    • アプリ権限（管理者 / マネージャー / 社員）
    • マネージャーの場合は「兼任先事業所」を選択
  3. 「招待を送信」をクリック
  4. 入力したメールアドレスに招待リンクが届く（1時間有効）
  5. 本人がリンクを開いてパスワード設定 → ログイン可能

社員一覧のフィルター

  • 在籍 / 退職 切替
  • 事業所別 / 役職別 / 名前検索

社員詳細（行をクリック）

  • 基本情報 / 連絡先 / 緊急連絡先
  • 雇用情報（雇用形態・契約期間・有給残）
  • 資格・スキル
  • 研修受講履歴
  • AI診断結果（管理者 / マネージャーのみ閲覧可。本人は見られない）

在職に戻す / 退職にする

  • 退職: 詳細ページの「退職処理」ボタン → 確認ダイアログで実行。同時に auth.users が BAN される
  • 在職に戻す: 退職済み社員の詳細から「在職に戻す」ボタン → BAN 解除
自分自身は退職処理できません。

カスタムフィールド

事業所ごとに独自項目を追加できます（管理者のみ）。 「設定 → カスタムフィールド」から定義 → 全社員の詳細画面に項目が追加されます。

5. シフト作成と公開

管理者 マネージャー シフト統括

シフト・送迎モード →「シフト表」（/admin/shifts）

シフト公開は 下書き → 仮シフト（職員確認中）→ 公開中 の3段階です。

① シフトを生成する（下書き）

  1. 上部の月セレクタで対象月を選択
  2. 上部に「下書き」バッジが表示される状態を確認
  3. 「自動生成」ボタンをクリック → 職員設定（および存在すれば利用予定）から自動でシフトを組む
    • 利用予定が未登録でもシフト生成は可能（職員が1名以上いれば押せる、2026-05-15 仕様変更）
    • 利用予定が未登録の場合は最低出勤人数だけを目安に組まれる
  4. 生成後、必要に応じてセルをクリックして手動で職員を差替・追加

② 仮シフトにする

  1. 全行揃ったら右上の「仮シフト確定 → 職員確認」ボタンをクリック
  2. ステータスが「下書き ● + 未完成 ⏳」から「仮シフト（職員確認中）」に変わる
  3. この時点で社員側にも見える状態になります（/my/shifts に「仮シフト（確認中）」黄バッジで表示）。社員は内容を確認し、問題あれば「シフト変更申請」を提出可能

③ 公開する

  1. 「公開する」ボタンをクリック
  2. 確認モーダルで「公開」を押すとステータスが「公開中」に
  3. 公開後、社員側 /my/shifts のバッジが「仮シフト（確認中）」黄から「公開中」緑に切り替わり、警告メッセージが消える（内容自体は仮シフト段階から見えている）
  4. 送迎割当も自動で同じ状態に連動

公開取消（再編集したい時）

  1. 「公開取消」ボタンをクリック
  2. ステータスが「仮シフト」に戻り、編集可能になる
  3. 再度「公開する」で再公開
公開済みシフトを再生成しようとした時: 「公開済みのシフトは再生成できません。先に『公開取消』してから再生成してください。」と表示されます。 誤って公開済みデータを上書きしないための保護です。

シフト生成ロジックの要点

  • 最低出勤人数: max(ceil(利用人数 / 2), 3)
  • 有資格者最低: 事業所設定値（デフォルト 2名）
  • 休み希望（希望休）は自動で除外される
  • 条件未達のセルは赤ハイライト

公休 / 希望休 の区別（migration 157、2026-05-15〜）

シフト作成画面のセル編集モーダルでは「休み」が 2 種類 選べます。

種類 色 由来 出せる人
公休 ■ 青 管理者が会社都合などで決めた休み 管理者 / マネージャー / シフト統括
希望休 ■ 金 社員が休み希望として出した休み（shift_requests 由来） 社員本人（管理者経由で確定）
  • 社員からは「公休」を出すことはできません（管理者専用）
  • 自動生成では社員の希望休が反映される（公休は管理者が手動でマーク）
  • シフト表上の統計には「公休 N」「希望休 N」が個別に表示される

6. 利用予定の取り込み（Excel優先）

管理者 マネージャー シフト統括

シフト・送迎モード →「利用表」（/admin/shifts/schedule）

月次の利用予定を取り込む方法は Excel貼付（推奨） と PDF取込 の 2 種類です。Excel貼付の方が速くて確実なので、こちらを基本に運用してください。

① Excelから貼り付け（推奨）

  1. デイロボから出力した利用予定の Excel ファイルを開く
  2. Excel の左端にある行番号（1, 2, 3...）をクリック＆ドラッグして、ヘッダー行と児童名列を含む範囲を「行ごと」選択
    • セルだけ選ぶと範囲がズレることがあるため、必ず行番号で「行全体」を選択
  3. Ctrl + C でコピー
  4. 利用表ページ右上の📋（Excel貼付）ボタンをクリック →「Excelから貼り付け」モーダルが開く
  5. 「一括モード（Excel経由）」タブが選択されていることを確認
  6. テキストエリアに Ctrl + V で貼り付け → 自動で解析
  7. 確認画面で内容をチェックして「保存」 → DB に反映

対応フォーマット

  • 横型 … 1行目が日付、各セルに「迎 13:20 / 送 16:00」
  • 縦型 … 児童名・日付・迎え・送り の列
  • セル内改行がある Excel データもそのまま対応
⚠ デイロボ Web 画面から直接コピーするとタブが失われます。 その場合は「1児童モード（デイロボ直接貼付）」タブを使って、1児童ずつ貼り付けてください。

② PDF取込（補助）

Excel が手元に無い場合の代替手段です。基本は Excel 貼付を使ってください。

  1. 右上の「PDF」ボタンをクリック
  2. PDF を選択（最大 20MB）
  3. Claude API（claude-sonnet-4-20250514）が自動解析（数秒〜数十秒）
  4. 確認画面で抽出結果を確認
    • 児童名 / 日付 / 送り時刻 / 迎え時刻 / エリア
    • 「追・休」「定・休」などの特殊ステータスはエリア欄に表示される
  5. 内容を確認して「保存」をクリック → DB に反映
PDF 解析は AI 処理のため、特殊フォーマットやレイアウト崩れがあると精度が落ちます。確認画面で必ず内容をチェックしてください。

取込後の編集

  • 利用表のセルを直接クリックして時刻・エリアを修正
  • 児童名が辞書に無い場合は児童マスタへの新規登録ダイアログが出る

ANTHROPIC_API_KEY 未設定の場合

PDF取込は使えなくなりますが、Excel貼付は通常通り利用可能です。手入力モードも併用してください。

取込全般の注意
  • 1回の取込で1ヶ月分を想定
  • 既存データは月単位で上書き（同日同児童は新しい値で置換）
  • 出席判定は「送り時刻 or 迎え時刻あり、かつステータスがキャンセル待ちでない」

7. 送迎表

管理者 マネージャー シフト統括

シフト・送迎モード →「送迎表」（/admin/shifts/transport）

送迎表の基本

  • 当日の送り（朝〜昼）と迎え（夕方）を時間軸で表示
  • 1便あたり最大 2名の職員を割当
  • 事業所設定で transport_enabled=false の事業所はメニューから消える

自動生成

  1. シフトを「仮シフト」または「公開中」にしておく
  2. 「送迎自動生成」ボタンをクリック
  3. ロジック:
    • ① 出勤者
    • ② 勤務時間内
    • ③ エリア一致
    • ④ 前後 30分以内なら同便に統合
    • ⑤ トリップ数を職員間で均等化
  4. 条件未達のセルは「未割当」赤ハイライト（空欄確定は禁止）

手動で調整

  • 職員セルをクリックして差替
  • ドラッグで便を移動

キャンセル待ち児童

attendance_status='waitlist' の児童はメイン送迎表からは除外され、 画面下部の「キャンセル待ち」セクションに表示されます。

週次送迎の出力

送迎表ページ上部の「週次送迎を出力」ボタン → PDF ダウンロード。 サイドバーから直接は遷移できません（出力ボタンに統合済み）。

8. 休み希望と承認

管理者 マネージャー シフト統括

シフト・送迎モード →「休み希望」（/admin/requests, /mgr/requests）

用語整理（migration 157 以降）

  • 希望休 … 社員が「この日休みたい」と希望として出した休み（このページで扱う）
  • 公休 … 管理者がシフト作成画面で直接マークした休み。社員からは申請できない
  • 旧バージョンの「公休」表記は全て「希望休」に置き換わりました

社員が希望休を出すフロー

  1. 社員画面の /my/requests
  2. 「希望休を提出」ボタン
  3. 日付 + 種別を選択:
    • 希望休（終日）
    • 有給休暇（paid_leave）
    • 終日勤務可（full_day_available）
    • 午前休（am_off）
    • 午後休（pm_off）
  4. 必要に応じて理由を記入 → 送信
  5. status='pending' で保存

マネージャー / 管理者が承認するフロー

  1. /admin/requests または /mgr/requests を開く
  2. 「承認待ち」リストから対象の申請をクリック
  3. 内容を確認して「承認」または「却下」
  4. 承認すると、その日の自動シフト生成でその職員が「希望休（金色セル）」として確定する

シフト変更申請（公開後の差替依頼）

  • 公開後の自分のシフトを変更したい時、社員が変更申請を出す
  • 「🔔 シフト変更申請 N件 承認待ち」が承認キューに表示
  • 出勤中の 管理者のみ承認可能（マネージャーは閲覧のみ）
  • 申請選択肢から「公休」は除外（公休は管理者専用のため）
注意:
  • 社員は自分の申請のみ書き込み可（RLS）
  • マネージャーは自事業所内の申請のみ承認可
  • 承認後にシフト作成画面で「希望休（金色）」として表示。公休（青色）とは別扱い

9. 利用料金表

管理者 マネージャー

シフト・送迎モード →「利用料金表」（/admin/shifts/output/billing）

月次の利用負担額（自己負担金）を集計します。

出席日数の判定

  • 「送り時刻 or 迎え時刻あり、かつ status != 'waitlist'」が出席
  • お休み / 欠席 / キャンセル待ちは出席に含めない
  • 時刻 NULL の planned / present は出席にカウントされない（ゴーストデータ対策）

自動計算される項目

  • 出席日数（上記ロジック）
  • おやつ消耗品代: 50円 × 出席日数（固定）
  • 公文代: children.kumon_monthly_fee × 1（児童ごとの月額。null なら計上しない）

手動入力する項目

  • 利用負担額: 月次で手動入力（上限 4,600 / 37,200 / 自由入力 / 無料 を選択）
  • 名古屋市は preschool も無償化対象（NAGOYA_FREE_PRESCHOOL_MUNICIPALITY）
  • 全国無償化: nursery_3 / nursery_4 / nursery_5 学年は自動で無料
注意: 利用負担額の精緻計算（出席日数 × 単価でクリップ）はデイロボに任せる。 月次料金表ページでは手動入力 + 自動集計の組み合わせ。児童属性として「1日単価」は持たない。

10. 日次出力 / 業務日報

管理者 マネージャー シフト統括

日次出力（/admin/shifts/output/daily）

当日の利用者一覧と出席状況を PDF / Excel で出力。

  • 児童名 / 送迎時刻 / 出席状況
  • 出席判定は「時刻あり、かつ waitlist でない」

業務日報（/admin/shifts/output/daily-report）

当日の業務記録テンプレート。

  • 出席児童 / 活動内容（自由入力）/ 特記事項 / 担当職員サイン欄

同席日数（/admin/shifts/output/staff-child-overlap）

特定職員と児童が一緒に過ごした日数を集計。個別支援計画の根拠資料として利用可能。

印刷

各出力ページの「印刷」ボタンから直接プリント可能。レイアウトは A4 縦/横を自動判定します。

11. 書類とタグ

管理者 マネージャー

社員管理モード →「書類管理」（管理者のみ /admin/documents）

書類テンプレートの作成

  1. PDF をアップロード（最大 20MB、PPTX は不可）
  2. PDF 上にタグを配置:
    • タグキー（英数字）+ ソースタイプ（社員データ / 法人情報 / フォーム入力 / 固定値 / カスタムフィールド）
    • 配置はドラッグで移動、サイズはハンドルで調整
  3. 同一テンプレートに同じタグキーは1つまで（UNIQUE）
  4. フォント: IPAex 明朝 固定（MS 明朝相当）
  5. 装飾（太字 / 斜体 / 下線 / 色 / 回転）は不可

タグの種類

  • 社員データ: 氏名 / 入社日 など、社員情報から自動差込
  • 法人情報: 法人名 / 代表者名 など
  • フォーム入力: 書類作成時にフォームで入力する項目
  • 固定値: 設定した文字列をそのまま差込
  • カスタムフィールド: 自由項目（事業所別に追加）の値

書類を生成する

  1. テンプレート一覧から対象を選択
  2. 対象社員を指定
  3. form_data タグがあればフォーム入力
  4. 「生成」 → PDF ダウンロード

必須/任意の判定

タグの required + source_field から lib/field-applicability.ts が自動判定。 旧 VISIBILITY_CONDITIONS は migration 119 で廃止済み。

上限: 1テナントあたり最大 10 件（MAX_DOCUMENTS_PER_TENANT）

12. 研修

管理者 マネージャー

社員管理モード →「研修」（/admin/trainings, /mgr/trainings）

研修を作成

  1. 「研修を追加」ボタン
  2. タイトル / 説明 / 受講対象（全員 / 事業所別 / 役職別）
  3. 動画 URL or PDF 資料を添付
  4. 受講確認方法を選択:
    • 視聴完了報告のみ
    • 視聴 + 感想文（最低150文字）
    • 視聴 + 確認テスト

受講状況の確認

研修詳細ページで全対象者の進捗を一覧表示:

  • pending（未受講）
  • passed（合格）
  • failed（不合格）
  • resubmit（再提出待ち）

感想文 / テストの採点

  • マネージャー / 管理者が内容を確認 → 合格 / 不合格 / 再提出要求
  • 再提出を要求した場合、社員側に通知（視覚通知のみ、音なし）
感想文の最低文字数は TRAINING_SUMMARY_MIN_CHARS=150。 AI診断結果との連動は無し（研修は独立）。

15. 設定と事業所追加

管理者 マネージャー

社員管理モード →「設定」（/admin/settings）

設定タブ

  • 法人情報（管理者のみ編集可）
  • カスタムフィールド管理（管理者のみ）
  • 役職（positions）管理
  • カテゴリ管理
  • 振込銀行情報（最大 3 件、MAX_PAYROLL_BANKS_PER_TENANT）

事業所を追加（管理者のみ、/admin/facilities）

  1. 「事業所を追加」ボタン
  2. 事業所名 / 住所 / 表示順
  3. 機能フラグ:
    • shift_enabled: シフト機能を使う（false ならシフトモードの事業所セレクタから除外）
    • transport_enabled: 送迎機能を使う（false ならメニューから送迎表が消える）
    • shift_only_mode: 「シフト/休み希望/職員管理/ダッシュボード」だけに絞る（migration 125）
  4. 保存後すぐにシフトモードのセレクタに反映

事業所設定（シフトモード側、/admin/shifts/facility-settings）

  • 営業時間 / 定休日
  • エリア定義（送迎の地域分け）
  • 有資格者最低人数
  • 児童の最低職員比

アプリ権限管理（/admin/access-matrix、管理者のみ）

  • 全社員のアプリ権限（管理者 / マネージャー / 社員 / シフト統括）一覧
  • ダイアログでロール変更可能
  • マネージャーの兼任先事業所を追加・削除

16. トラブルシュート

管理者 マネージャー シフト統括

よくある質問

Q. ログインできない

  • 退職処理されていないか 管理者に確認（「退職処理済みのアカウントです」表示）
  • パスワードリセットを試す（メールは1時間有効）

Q. シフトを「公開」したのに 社員に表示されない

  • publish_status が本当に 'published' になっているか確認（バッジが「公開中」かチェック）
  • 社員自身の facility_id とシフトの facility_id が一致しているか
  • 社員のブラウザでリロードしてもらう

Q. PDF取込で「APIキー未設定」エラー

  • 環境変数 ANTHROPIC_API_KEY が未設定
  • 管理者に連絡して .env.local / Vercel 環境変数を確認してもらう
  • 暫定対応として手入力 or Excel貼付を使用

Q. 送迎表が「未割当」（赤）のまま

  • 該当時刻に出勤予定の有資格者が不足
  • 該当エリアの担当が不在
  • 手動で職員を割当 or シフトを調整

Q. 利用料金表の出席日数がおかしい

  • 利用表で「時刻あり、status != waitlist」が出席判定（lib/logic/attendance.ts）
  • お休み / 欠席 / キャンセル待ちはカウントされない
  • 時刻 NULL の planned / present もカウントされない（ゴーストデータ対策）

Q. 社員の画面で「自分のシフト」が出ない

  • 該当月のシフトが「公開中」になっているか確認
  • 自分宛の割当があるか確認
  • ブラウザキャッシュをクリアして再ログイン

Q. 招待メールが届かない

  • 迷惑メールフォルダを確認
  • 1時間以上経過 → 失効。管理者に再送依頼

Q. ロール変更が反映されない

  • /admin/access-matrix で変更後、対象の社員に再ログインしてもらう
  • middleware のロール判定はセッション単位

連絡先

  • 操作方法でこのマニュアルでも分からない場合は、システム管理者にお問い合わせください
  • バグや改善要望はシステム管理者経由で開発元へ
